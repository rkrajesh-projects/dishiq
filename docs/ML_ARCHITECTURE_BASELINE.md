# ML ARCHITECTURE BASELINE

## Current ML
The repository currently contains the following implemented ML models (located in `/ml/` and integrated via `MLService` in the backend):

1. **TF-IDF Recommender**: Retrained on 1,026 recipes. Uses `TfidfVectorizer` (ngram_range=1,2, max_features=500) and Cosine Similarity. Artifact: `recipe_tfidf.joblib`.
2. **Random Forest Suitability**: Supervised regression model predicting general recipe quality. Features include prep_time, servings, ingredient_count, diet encoding. Artifact: `suitability_rf_model.joblib`.
3. **K-Means Recipe Clustering**: Unsupervised grouping based on structural features. Discovered K=6 clusters with auto-generated descriptions based on centroids. Artifact: `recipe_kmeans.joblib`.
4. **SentenceTransformer Product Matcher**: Pre-trained `all-MiniLM-L6-v2` (384-dimensional) used for semantic matching of raw ingredients to grocery products. Artifact: `product_embeddings.joblib`.

## Current AI
The AI layer consists of a Cooking Assistant context endpoint (`/api/cooking/context/{session_id}`). It provides structured metadata (current instruction, next instruction, ingredients, progress percentage) to be consumed by an external LLM/AI. The LLM itself is not embedded directly in this application code; the backend acts as a context provider.

## Current optimization
Cart optimization (`cart_optimization_service.py`) deterministically finds the cheapest combination of grocery products across multiple providers (e.g., Demo FreshBasket, Demo LocalGrocer) to fulfill a recipe's ingredient requirements.

## Current recommendation system
The primary recommendation engine (`RecommendationService`) uses a multi-factor scoring algorithm:
- Base Score (1.0)
- Dietary Match (+0.5)
- Cooking Time Compatibility (+0.2)
- TF-IDF Text Similarity (Cosine Similarity * 0.4)
- Pantry Ingredient Overlap (+0.1 per matching item)
- Rating Boost (Average Rating / 5.0 * 0.3)
- Random Forest Suitability (Normalized RF Score * 0.15)

## Dataset
- **SQLite Database (`dishiq.db`)**: Contains 1,026 recipes, 1,300 ingredients, and 8,903 recipe-ingredient mappings.
- **CSV Datasets (`dataset/`)**: Contains Food.com interaction datasets (`interactions_train.csv`) used as proxy labels for training the Random Forest suitability model.

## Missing ML capabilities
While the backend models and service layers are fully trained and integrated via API endpoints (`/api/ml/...`), the following gaps remain:
1. **Frontend Integration**: The React frontend does not currently display the K-Means clusters, Suitability Scores, or "Similar Recipes" generated by the ML layer.
2. **Personalized User ML**: The current models predict *general* quality and similarity, but lack true user-specific collaborative filtering based on individual DishIQ user history (because historical data inside DishIQ is too sparse).
3. **LLM Orchestration**: The cooking assistant context exists, but a true in-app conversational AI interface interacting seamlessly with the MCP tools is not fully mapped in the frontend.
